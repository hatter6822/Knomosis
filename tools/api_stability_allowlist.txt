# tools/api_stability_allowlist.txt — frozen debt for `api_stability_audit`.
#
# Each line is a `path:line` key for a term-level API-stability binding
# written WITHOUT a type ascription:
#
#     let _ := @some_theorem          -- pins only that the NAME exists
#
# CLAUDE.md's "Test patterns" section promises these tests fail
# elaboration when a signature changes.  Without the ascription they do
# not: reordering hypotheses, weakening a conclusion, or adding a
# parameter all still elaborate, and the test still reports PASS.  The
# fix per binding is to write the theorem's full type:
#
#     let _proof : <the theorem's type> := some_theorem
#
# This file FREEZES the pre-existing occurrences so the gate can block
# NEW ones immediately while the existing set burns down.  Do NOT add
# entries for new code — add the ascription instead.
#
# The key is `path:line` and deliberately omits the line text: a
# binding that gains its ascription simply stops matching (and can be
# deleted from here), and one that moves is re-reported, which is the
# correct direction for a burn-down list.
#
# Regenerate after a bulk conversion with:
#     lake exe api_stability_audit 2>&1 \
#       | grep -oE '^  [^:]+\.lean:[0-9]+' | sed 's/^  //' | sort -u
#
# Comments start with `#`; blank lines are ignored.
